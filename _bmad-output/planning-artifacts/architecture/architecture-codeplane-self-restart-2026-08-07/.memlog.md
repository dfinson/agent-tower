- (constraint) Inherited parent AD-1: shared product semantics use ports and adapters, so lifecycle control enters through a declared port and not route-level process logic.
- (constraint) Inherited parent AD-2: local-daemon remains autonomous and cannot require Kubernetes or a hosted service.
- (constraint) Inherited parent AD-10 and AD-11: SQLite remains canonical for product state, history, idempotency, and operation records; any supervisor journal is only a restart-adoption receipt and never a peer product authority.
- (constraint) Inherited parent AD-12: clients converge after disconnect by replay or snapshot; remote restart may cause bounded transport loss but must preserve one stable endpoint and retry identity.
- (constraint) Inherited parent AD-17: local mode promises crash-consistent recovery rather than HA; the established planned restart target is under 60 seconds.
- (constraint) Inherited parent AD-18, AD-19, AD-25, AD-27, and AD-32: preserve structured observability, shared authenticated ingress rules, local-only tunnel support, existing application conventions, and the logged-in OS-user trust boundary.
- (direction) Use an out-of-process lifecycle supervisor as the stable parent of the CodePlane application and any managed tunnel; the application is a replaceable child and cannot own its own restart.
- (decision) AD-1 binds all local self-restart paths: only the lifecycle supervisor may start, stop, replace, or signal the CodePlane application process; API routes and agents request lifecycle operations through LifecycleSupervisorPort and never signal listeners or process groups directly; prevents self-termination and competing restart owners.
- (decision) AD-2 binds remote access: the supervisor owns the managed Dev Tunnel or Cloudflare connector as a sibling of the application, preserves the same public origin and authentication launch inputs across application replacement, and restarts only the application child; prevents the remote control path from disappearing permanently.
- (decision) AD-3 binds restart acceptance and retries: the application commits a canonical restart operation and idempotency digest in SQLite before arming the supervisor over OS-user-restricted IPC; the supervisor fsyncs a hash-bound adoption receipt before acknowledgement; identical retries return the original operation and a different digest conflicts; prevents ambiguous duplicate restarts.
- (decision) AD-4 binds lifecycle phases: requested, preparing, quiescing, stopping, starting, verifying, recovering, succeeded, failed, and rolled_back are explicit bounded phases; one supervisor-held restart lease serializes operations; the receipt records only operation ID, digest, launch generation, phase checkpoint, and timestamps needed for crash adoption; prevents overlapping or unresumable replacement.
- (decision) AD-5 binds launch reproducibility: every child starts from an immutable RuntimeGeneration plus a persisted secret-free LaunchSpec containing executable, generation ID, source fingerprint, bind address, app port, tunnel provider/name/origin, feature flags, config references, and expected version; secrets remain references or inherited protected values; prevents a restart silently changing cwd, remote mode, credentials, or code.
- (decision) AD-6 binds preparation and rollback: candidate frontend and backend artifacts are built and validated into a new immutable generation while the current application remains available; jobs are quiesced before the final source fingerprint and activation; build or preflight failure leaves the current child running, while post-switch health failure reactivates the prior known-good generation; prevents avoidable outage and unrecoverable broken activation.
- (decision) AD-7 binds job handling: the initiating job is not special after the restart response is accepted; the supervisor independently requests bounded quiescence for every active managed job, records jobs that did not acknowledge, stops only after policy permits, and relies on existing startup recovery rather than issuing duplicate resume calls; prevents the initiator from killing its own coordinator and avoids double recovery.
- (decision) AD-8 binds remote client behavior: POST restart returns HTTP 202 with operation ID before the not-before activation time; SSE, MCP, and browser connections may disconnect during the bounded window, reconnect to the same origin, and query the canonical operation by ID or replay events; clients retry the original idempotency key when acceptance is uncertain; prevents false failure and duplicate execution.
- (decision) AD-9 binds authorization: restart and generation activation require the existing highest local lifecycle authority, are denied to agents unless operator policy explicitly delegates that exact operation, and cannot be approved by the initiating job; supervisor IPC uses OS-user permissions plus a per-boot capability; prevents remote or agent privilege escalation.
- (decision) AD-10 binds crash recovery: on supervisor or application startup, the supervisor adopts at most one valid receipt, compares it with canonical SQLite when available, and either continues from the last safe phase, rolls back, or records an explicit reconciliation failure; stale or hash-mismatched receipts never execute; prevents replay after crashes or source changes.
- (decision) AD-11 binds the recursion boundary: remote self-restart replaces only the application RuntimeGeneration; replacing the supervisor itself requires a host service manager or independent local command and is reported as unsupported when that manager is absent; prevents claiming that a process can guarantee resurrection of its own lifecycle root.
- (decision) AD-12 binds evidence: each transition emits structured logs and canonical domain events correlated by operation ID, request ID, actor, generation, child PID, and health result; secrets and raw tunnel credentials never enter either surface; prevents restart diagnosis depending on terminal output.
- (assumption) A-1 [ASSUMPTION]: v1 implements supervised self-restart for local-daemon mode only; Kubernetes uses its existing rollout controller and does not reuse this host supervisor.
- (assumption) A-2 [ASSUMPTION]: the application outage target is under 60 seconds, preparation may take longer while the current application remains available, and remote clients tolerate transient disconnects rather than continuous HA.
- (assumption) A-3 [ASSUMPTION]: direct legacy cpl up remains available for development but advertises restart capability unavailable; remote self-restart is enabled only when the supervisor and durable IPC handshake are active.
- (question) Open question for implementation planning: whether v1 RuntimeGeneration is a built wheel plus per-generation environment or an immutable source snapshot; the contract requires immutability, source fingerprinting, validation, and rollback regardless of packaging.
- (decision) AD-2 is strengthened: the supervisor owns the stable public listener and a transport-transparent edge gateway, proxies normal HTTP, SSE, MCP streamable HTTP, and WebSocket traffic to the application on a private loopback port, and serves only supervisor health plus operation-scoped restart status while the child is unavailable; the managed tunnel always targets the gateway; prevents a blind remote failure window.
- (decision) AD-9 is strengthened: the application-authenticated restart response may mint a high-entropy, short-lived, read-only operation status capability whose hash is stored in the supervisor receipt; the gateway accepts it only for that operation status endpoint and never for restart creation or other APIs; prevents duplicated application authentication inside the supervisor while retaining remote observability during outage.
- (decision) AD-5 is strengthened: the public port belongs to the supervisor and the LaunchSpec assigns the application a private loopback port; application readiness includes version, generation ID, and supervisor protocol compatibility before the gateway switches upstream.
- (decision) Reviewer fix for AD-2 and AD-9: the gateway exposes separate local and tunnel-ingress listeners, strips all inbound forwarding and CodePlane identity headers, classifies the listener as local or remote, and signs the reconstructed client class and address with a per-boot HMAC; the child trusts localhost bypass only for a valid gateway-signed local classification and otherwise applies normal remote authentication; prevents the loopback proxy from authenticating every remote request as localhost.
- (decision) Reviewer fix for AD-4: add rollback_starting, rollback_verifying, and unrecoverable phases; requested and stopping may transition to failed; rollback uses its own bounded start and verify phases; rollback failure terminates as unrecoverable with the gateway and supervisor alive for local recovery.
- (decision) Reviewer fix for AD-3: requested operations that are not armed before the arm deadline are failed by LifecycleService on call failure, startup, or the next lifecycle observation and do not block later operations; only armed-or-later nonterminal work holds serialization.
- (decision) Reviewer fix for AD-8: server-side response flush cannot prove client receipt, so activation waits for the gateway to finish the complete response plus a configured grace floor; safety under a lost response comes from the same idempotency key and stable operation identity, not from a delivery claim.
- (decision) Reviewer fix for AD-2 streaming cutover: at quiescence the gateway emits server.restarting then orderly closes SSE when writable, sends WebSocket close code 1012, ends MCP streamable responses orderly, drains bounded ordinary requests, and resets only after the drain deadline; clients still use operation polling when no planned signal arrives.
- (decision) Reviewer fix for AD-2 and AD-8 tunnel adoption: supervised remote mode requires a durable provider and resolved tunnel name or hostname; the supervisor persists and reuses this identity across its own crash or host restart before restoring the child; it owns process handles and health probes and never uses process-name scanning such as pgrep for tunnel ownership.
- (decision) Reviewer fix for AD-7: quiescence adds new acknowledgement and deadline tracking; it classifies current non-recoverable states before stopping. Plan-mode waiting_for_approval is restart-unsafe under existing behavior, so default restart fails without stopping, while an explicitly forced restart records that the job will fail through existing recovery. Recoverable jobs use the existing startup recovery path without a duplicate resume loop.
- (decision) Reviewer fix for AD-6: a final source fingerprint mismatch after jobs quiesce resumes every acknowledged job, fails the lifecycle operation, and leaves the current child serving; no stopped-child path begins.
- (decision) Reviewer fix for AD-10: the fsynced receipt is authoritative only for supervisor-owned phases reached while the application cannot write SQLite; a later receipt phase for the same matching operation is normal. The supervisor never opens SQLite. It adopts from the receipt and safe launch rules, then the ready child validates identity through repositories and appends the allowed receipt history to canonical SQLite; only identity, digest, generation, launch hash, or phase-sequence mismatch is conflict.
- (decision) Reviewer fix for AD-9 status secret: the application mints the high-entropy raw capability, computes HMAC-SHA-256 with the per-boot supervisor key, sends only the digest during arm, and returns the raw token only to the client; the gateway necessarily receives the raw Authorization value transiently when validating but never persists or logs it. Status polling is constant-time and rate-limited per operation and source.
- (decision) Reviewer fix for AD-9 approvals: lifecycle authorization is synchronous and complete before requested is committed; v1 has no asynchronous approval-wait phase. Agent-triggered requests require a pre-existing explicit grant and cannot pause awaiting self-approval.
- (decision) Reviewer fix for AD-6 packaging: restart preparation performs no network dependency resolution. Code-only generations reuse the validated active environment only when dependency-lock hash matches; dependency-changing generations require a complete prevalidated offline wheelhouse and new environment, otherwise preparation fails while the current child serves.
- (decision) Reviewer fix for AD-9 evidence: cross-platform qualification must prove supervisor control IPC rejects a different local OS user, including explicit Windows named-pipe DACL or equivalent enforcement, in addition to proving exact-child signaling.
- (assumption) A-2 correction: the under-60-second local application outage target is introduced by this feature as an assumption; it is not inherited from parent AD-17.

- (decision) AD-3 amended: no lifecycle database or idempotent product operation exists; the parent writes one atomic helper request file, the helper claims it by exclusive rename, and the parent returns only after a started marker proves the helper opened its log and adopted the request.

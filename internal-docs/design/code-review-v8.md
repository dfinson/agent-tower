# Code Review Experience — E2E Design (V8)

## Overview

Replace the current flat diff + separate analytics panels with a single layered
diff view that surfaces coverage, impact, and motivation inline. The reviewer
never leaves the diff — everything is an expansion of it.

---

## Layout

```
┌─────────────────────────────────────────────────────────────────┐
│ [Changes ×] [config_validator.py ×]              ← tab bar      │
├──────────┬──────────────────────────────────────────────────────┤
│ Changed  │ [⊙ Impact] [⊙ Coverage] [⊙ Motivation]    file.py  │
│ files    │─────────────────────────────────────────────────────│
│          │                                                      │
│ ● file1  │  40  40    """Validates config..."""                  │
│   file2  │  42      −  def validate_config(self, ...):          │
│   file3  │      42  +  def validate_config(self, *, schema...): │
│          │  43  43      """Validate config..."""                 │
│          │      44  +    if schema is not None:                  │
│          │      45  +      return self._validate_with_schema(...)│
│          │  ─── WHY THIS CHANGED ────────────────────────────── │
│          │  The validate_config signature lacked a schema...     │
│          │  ─── IMPACT · 5 callers affected ──── [1F][1U][3T] ─ │
│          │    ▶ FAIL  test_validate_strict_mode  test_config:72  │
│          │    ▶ untst load_environment           env_svc:34      │
│          │    ▶ pass  apply_overrides            config_loader:88│
│          │                                                      │
└──────────┴──────────────────────────────────────────────────────┘
```

**Left panel** — changed file list with M/A/D badges, active file highlighted.
Clicking a file scrolls the diff panel to that file.

**Right panel** — unified diff with three toggleable layers injected as view
zones between diff lines.

---

## Three Independent Layers

Each layer has its own toggle switch in the toolbar. All default ON. Toggling one
does not affect the others.

### 1. Coverage (gutter dots)

Small colored circles in the left gutter of every added line:

| Color  | Meaning                        | Hover tooltip           |
|--------|--------------------------------|-------------------------|
| Green  | Line covered by passing tests  | "Covered by N test(s)"  |
| Red    | Line not covered by any test   | "Not covered"           |
| Yellow | Lint/static analysis finding   | "Lint: D401 ..."        |

**Click green dot → popover** listing covering tests, each with:
- Status icon: ✓ passed, ✗ failed, ○ not run (with title tooltip)
- Test name and file:line
- [Peek] button → opens peek modal showing surrounding source
- [↗] button → navigates to test source in editor

### 2. Motivation (view zone)

A standalone block injected after the last changed line of each symbol,
labeled "WHY THIS CHANGED". Independent of impact — always visible when toggled on.

Content: 2-4 sentence prose paragraph in third-person, abstract voice. Explains
what prompted the change (upstream finding, bug, prior read), cites concrete
file paths and function names from the agent's transcript. Never restates what
the diff already shows.

**Data source**: `job_telemetry_spans.motivation_summary` (file-level) and
`job_telemetry_spans.edit_motivations` (per-edit). Generated by
`MotivationService` calling the utility model against preceding_context.

### 3. Impact (expandable zone)

A collapsible panel injected after the motivation zone for each changed symbol.

**Collapsed state** (single row):
```
▶ IMPACT · 5 callers affected by signature change  [1 FAIL]
```

- "IMPACT" label in a bordered badge
- Human-readable summary (e.g. "5 callers affected by signature change",
  "new function · 1 caller")
- Pill for actionable status only (FAIL count). Coverage is not restated here —
  it's visible on the lines themselves.

**Expanded state** — list of caller cards:

Each caller card shows:
- Expand chevron (▶)
- Coverage dot (same as diff gutter: green = covered, red = uncovered)
- Function name (monospace)
- File:line location
- [Peek] button (visible on hover)

**Click caller row → inline source preview** (3-5 lines of context, call site
highlighted). Source lines have coverage dots in the gutter, identical to the
main diff view. This is NOT a separate panel — it expands in-place below the row.

**Click [Peek] → modal** with wider source context (~13 lines), highlighted call
site, header showing `file:line`, [Go to source ↗] button, [×] close.

**Test failures** appear inline below the failing caller row:
```
✗ test_validate_strict_mode
TypeError: validate_config() got unexpected keyword argument 'strict' as positional
```

## Interactions

| Action                    | Result                                        |
|---------------------------|-----------------------------------------------|
| Toggle switch off         | Hides all elements of that layer instantly     |
| Click impact header       | Expand/collapse caller list                    |
| Click caller row          | Expand/collapse inline source preview          |
| Hover [Peek] button       | Button appears (hidden until hover)            |
| Click [Peek]              | Modal with source context + Go to source       |
| Click [Go to source ↗]   | Opens file at line in editor, closes modal     |
| Click green gutter dot    | Popover with test list + status + actions      |
| Hover any gutter dot      | Tooltip with coverage/lint summary             |
| Click file in sidebar     | Loads that file's diff in the right panel      |
| ESC                       | Closes peek modal or popover                   |

## Implementation Phases

### Phase 1 — Diff view with file sidebar
- Unified diff renderer (replace current flat diff)
- File navigation sidebar with change badges
- Hunk headers, line numbers, +/−/context styling

### Phase 2 — Coverage layer
- Gutter dots on added lines (data from CodeRecon)
- Hover tooltips
- Click-to-expand test list popover with status icons
- Peek + Go to source actions on each test

### Phase 3 — Motivation layer
- View zones injected per-symbol after changed lines
- Data from `MotivationService` (already populating DB)
- Toggle independent of other layers

### Phase 4 — Impact layer
- Collapsible per-symbol impact zones
- Caller cards with coverage chip + source location
- Inline source preview on expand
- Peek modal with Go to source
- Test failure rendering under failing callers

---

## Constraints

- No internal CodeRecon labels (tier, confidence, certainty) exposed to UI
- Caller coverage uses the same gutter dots as the diff — no separate labels or chips
- No redundant signature diff inside the impact zone (the actual diff above shows it)
- Test failures appear under the relevant caller row, not as a top-level section
- Collapsed impact zone = single header row only
- Motivation is per-symbol, not per-file
- Everything rendered as view zones within the diff — no separate tabs or panels

---

## Tooltips

Tooltips are reserved for genuinely ambiguous elements — icons or abbreviations
whose meaning isn't immediately clear from context. Self-explanatory labels
(toggles, "Peek", "Go to source", ×, chevrons) do not get tooltips.

| Element | Tooltip text |
|---------|-------------|
| File badge `M` | Modified |
| File badge `A` | Added |
| File badge `D` | Deleted |
| Coverage dot (green) | Covered by N test(s) |
| Coverage dot (yellow) | Not covered by any test |
| Popover `↗` icon | Open in editor |
| Test status `✓` | Passed |
| Test status `✗` | Failed |
| Test status `○` | Not run |
